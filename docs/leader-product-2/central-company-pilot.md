# Local Central / Company protocol pilot — 2026-11-17

Implemented in dev/platform-pilot/pilot.cjs; `npm run test:platform-pilot` uses real loopback HTTP listeners on ephemeral ports and closes them after tests. No imports from legacy runtime, .env, Prisma, Redis, 1C or deployment configuration. Fixture-only users/password/data, ephemeral tokens and Ed25519 keys; no public CLI listener or external endpoint defaults. Do not expose this harness as a service.

Central maps alice to alpha and bob to beta; session cannot request another company's audience. Discovery returns company-specific endpoint and signed pinned release set (alpha-1: qr/help 1.0.0; beta-4: qr 2.0.0). Opaque restricted tokens expire after 60s; central tracks session revocation. Company requests authenticate through an HTTP call to Central on EVERY request, with company-specific service credentials. Positive results are never cached. Central failure returns 503 even after prior authorization; universal session tokens and wrong-company/artifact audiences are rejected. Fixture record ownership enforced server-side.

Artifact service requires dedicated artifact audience and company/module entitlement, introspects online, and returns digest-addressed immutable bytes only for the authorized company. Manifests signed over exact payload bytes; no universal token forwarded to caller-selected URLs. Fixtures are byte probes, not executable business modules and not a production storage implementation.

Evidence: `node --test dev/platform-pilot/pilot.test.cjs` exit 0, 4 integration tests / 106.8ms. Verified two discovery/release assignments and signatures, repeated network introspection count, central-outage rejection after positive access, global/wrong audience/company denial, object lookup denial, forged introspection service denial, private artifact hash/access/tenant checks, online revoke propagation to discovery/Company/artifacts. This is real local HTTP integration, not PostgreSQL/native/device/load evidence.

Pending: shared versioned contract package with APP (currently matching semantic payload shape), persistent identity/license/RBAC mapping, authenticated deployment configuration, delegated Help operations, API compatibility windows, key rotation, TLS/service authentication, bounded queues/retention/observability/rate limits and actual immutable artifact storage. Do not call the pilot a ready SaaS. Existing production-like legacy API remains unexposed and unchanged by this slice, including known socket/scheduler findings.

## Compiled-artifact registration and current rights — 2026-11-17
`startPilot({releases:[{release,files:Map}]})` now accepts explicitly supplied local compiled packages in memory, verifies every digest/size before atomically registering an immutable company/release id, and refuses id reuse with changed content. Registry blobs retain multiple company/release/module grants: identical shared Re.Pack chunks do not overwrite another owner. No arbitrary disk path, external URL, upload endpoint or production registration is added. `assignRelease`/`setModules` are fixture controls, not unauthenticated HTTP admin APIs.
Artifact tokens bind the assigned release at issuance. Existing tokens retain that release for their remaining 60s lifetime during assignment changes, while every request still introspects current user grants/revocation. New tokens do not expose old unassigned files; old tokens cannot expand privileges when grants grow. Discovery signs a user-entitled projection of the company's pinned set and returns the corresponding current module list. Revoked accounts also fail new login. Binary HTTP responses use private/no-store; immutable durable caching belongs to the tenant/user client adapter.
Evidence: pilot HTTP tests 7/7, including shared blobs across companies/modules, old/new token assignment separation, current grant reduction, signed reduced discovery, no token privilege expansion, account revoke and atomic failed registration. Cross-fork actual Re.Pack delivery test passed locally (APP `platform-host/dev/release/pilotDelivery.test.cjs`, explicit LP2_API_PILOT_ROOT); signatures verified with WebCrypto, per-file HTTP introspection counted, QR updated without Help downloads, interruption by revoke retained previous beta set, installed signatures/cache verified after Central stopped. This is Node filesystem/SQLite + real HTTP acceptance; no native remote execution or browser storage claim.

Web host acceptance may pass explicit webOrigins to startPilot. Only canonical http loopback origins are accepted; default allows none. CORS echoes only an allowlisted origin with Vary: Origin, no credential flag/wildcard, and preflight permits only GET/POST + authorization/content-type. All Central/Company/artifact authentication/introspection remains required on real requests. This is isolated local browser-test support, not an external domain configuration.
